# ПО для ПВ — контроллер Salda RIS 400P на KinCony KC868-A8

Своя плата управления приточно-вытяжной установкой Salda RIS 400P (старое поколение)
вместо утерянной заводской. Прошивка — ESPHome, работает полностью автономно.
Home Assistant и Алиса — только надстройка.

## Структура

```
firmware/
  ris400p.yaml                 главный файл: только параметры оборудования и уставки (substitutions)
  packages/
    board_kc868_a8.yaml        железо платы: I2C, PCF8574, реле K1–K8, входы X1–X8, выходы SSR
    network.yaml               Wi-Fi, резервная точка доступа, веб-интерфейс, API, OTA
    sensors.yaml               датчики: ADS1115 + опорное 3,3 В, назначение каналов
    fans.yaml                  режим вентиляции, смещение вытяжки, состояние вентиляторов
    heating.yaml               SSR ТЭНа (slow_pwm) и преднагревателя, уставка, ПИ, «Нагрев (зима)»
    protection.yaml            аварии, сброс, журнал во флеше, K8
    time.yaml                  NTP для журнала
    control.yaml               цикл управления: входы → VentSystem → реле и SSR
    drivers/
      ntc_ads1115.yaml         драйвер канала: NTC на ADS1115, ратиометрия, диагностика
      ntc_esp32_adc.yaml       драйвер канала: NTC на АЦП ESP32 (порт TEM/HUMI)
  include/vent_sensors.h       диагностика делителя (обрыв/КЗ/нет данных/опорное), пересчёт R
  include/vent_fans.h          последовательность пуска/останова, драйвер AC-мотора с отводами
  include/vent_heat.h          ПИ-регулятор с anti-windup, гистерезис преднагревателя
  include/vent_alarms.h        таблица аварий, ручной/авто сброс, журнал
  include/vent_system.h        верхний уровень: вентиляция + нагрев + защиты + обмерзание
  secrets.example.yaml         шаблон secrets.yaml
tests/
  test_vent_sensors.cpp        хост-тест vent_sensors.h
  test_vent_fans.cpp           хост-тест последовательностей вентиляции
  test_vent_system.cpp         хост-тест нагрева и защит (упрощённая тепловая модель)
docs/
  ssr_driver.md                ключи SSR (оптрон + MOSFET, fail-safe), цепь +12V_FLOW от реле давления
  ntc_inputs.md                подключение NTC: делители 22 кОм на ADS1115, t_supply на GPIO36
  fan_wiring.md                аппаратная блокировка скоростей K3→K2→K1 и K6→K5→K4
```

Позже: `ui.yaml` (OLED), датчик CO2.

## Сборка и прошивка

```bash
pip install esphome
cd firmware
cp secrets.example.yaml secrets.yaml   # заполнить; ключи: openssl rand -base64 32
esphome config ris400p.yaml
esphome compile ris400p.yaml
esphome run ris400p.yaml               # первый раз — по USB
```

## Проверка шага 2 на стенде (без силовой нагрузки)

1. Подать 12 В: ни одно реле не щёлкает, на портах TEM/HUMI 1/2 — высокий уровень.
2. В логе при старте — результат i2c-скана. Ожидаются адреса 0x22 и 0x24.
   Если они другие, поправить `pcf_inputs_address` / `pcf_relays_address`.
3. Веб-интерфейс `http://<IP>/`: пощёлкать K1–K8. Включение K2 при включённом K1
   сначала выключает K1, потом после паузы `fan_interlock_wait` включает K2.
   То же для K4–K6.
4. Замкнуть каждый вход X1–X8 на GND (X7 — реле давления через оптрон U3): в интерфейсе он становится «Включено» (= замкнут).
5. При перезагрузке все реле выключены (K8 тоже: «норма» пропадает, это fail-safe).

Для ручного щёлканья реле (начиная с шага 4) в `ris400p.yaml` поставить
`relays_internal: "false"` и `fan_logic_enabled: "false"`, после проверки вернуть.

## Проверка шага 3 на стенде

1. i2c-скан: появился адрес 0x48 (ADS1115).
2. `vref Опорное 3,3 В делителей` ≈ 3,3 В. Сравнить с мультиметром на той же шине.
3. Каждый NTC при комнатной температуре: сопротивление ≈ 10 кОм при 25 °C,
   температура совпадает с эталонным термометром ±1 °C. Разницу внести в `t_*_offset`.
4. Отключить датчик: состояние «обрыв», температура пустая, «неисправность» = ON.
   Для t_supply записать, какое напряжение показывает АЦП при обрыве:
   `adc_open_ratio` × 3,30 должно быть хотя бы на 0,05 В ниже.
5. Замкнуть вход датчика на GND: «КЗ».
6. Отключить ADS1115 от разъёма P19: через 5 с у трёх датчиков ADS «нет данных»,
   t_supply продолжает работать.

Каждый датчик даёт сущности: температура `t_*`, напряжение, сопротивление,
«неисправность» (ON и при старте, пока данных нет) и текст состояния:
норма / нет данных / обрыв / КЗ / вне диапазона / ошибка опорного 3,3 В.

## Шаг 4: логика вентиляции

Режим «mode Режим вентиляции»: Стоп / Скорость 1 / 2 / 3 (сохраняется при пропадании
питания). «exhaust_offset Смещение вытяжки»: −1 / 0 / +1 ступень, вытяжка в пределах 1…3.

| Пуск | Время (параметр) |
|---|---|
| Открыть заслонку K7 (если `damper_enabled`) | `damper_open_ms` 30 с |
| Пуск вытяжки | — |
| Пуск притока | `exhaust_lead_ms` 3 с после фактического пуска вытяжки |
| Нагрев разрешён | `heat_enable_delay_ms` 10 с непрерывной работы притока |

| Останов | Время (параметр) |
|---|---|
| Нагрев запрещён | сразу |
| Продувка притоком на текущей ступени | `purge_ms` 120 с |
| Стоп притока, затем стоп вытяжки | `exhaust_lead_ms` 3 с |
| Выбег, затем закрытие заслонки | `fan_rundown_ms` 15 с |

- Смена ступени: реле выключается, пауза `fan_switch_pause_ms` 1,5 с, включается новое.
  На время паузы и следующие 10 с нагрев запрещён.
- Возврат «Стоп → пуск» во время продувки — сразу в «Работа».
- После загрузки первые `boot_start_delay_ms` 10 с вентиляция не стартует, потом
  выходит на сохранённый режим через полную последовательность.
- Раздельная уставка притока/вытяжки: заменить расчёт `speeds_from_mode()` в `fans.yaml`
  на свой, последовательность не меняется.

Проверка на стенде (без моторов, по щелчкам реле и «fan_state Состояние вентиляции»):
выбрать «Скорость 2» → K7 → через 30 с K5 → через 3 с K2; переключить на «Скорость 3» →
K2 выкл, через 1,5 с K3; «Стоп» → 120 с продувки, K3 выкл, через 3 с K5 выкл,
через 15 с K7 выкл.

## Шаг 5: нагрев и защиты

Подробно — `docs/alarms.md`. Проверка на стенде, **без силового питания ТЭНов**
(вместо SSR — индикаторы ключей; датчики можно имитировать резисторами):

1. Пожар: разомкнуть X8 → все реле и оба SSR выкл сразу, K7 выкл, K8 выкл.
   «Сброс» при разомкнутом X8 не снимает аварию; после замыкания — снимает.
2. Внешний стоп: разомкнуть X4 → продувка 120 с, стоп; K8 остаётся включённым.
3. Термостат: разомкнуть X1 → SSR ТЭНа выкл сразу, продувка, стоп, ручной сброс.
   Перезагрузить контроллер до сброса — установка остаётся в стопе.
4. Поток: не замыкать X7 → через 30 с после пуска притока «Нет потока притока».
5. Перегрев: резистор ≈ 4 кОм вместо NTC притока (≈ +50 °C) → авария, продувка, стоп.
6. Обрыв датчика: отключить любой NTC → нагрев выкл, продувка, стоп; вернуть → пуск.
7. ПИ: уставка выше текущей температуры притока → «heater_pct Мощность ТЭНа» растёт,
   индикатор SSR мигает с периодом 10 с.
8. Преднагреватель: резистор ≈ 30 кОм вместо NTC выброса (≈ −2 °C) → преднагреватель вкл.

## Безопасность

Аппаратный термостат с ручным сбросом в силовой цепи ТЭНа обязателен
независимо от прошивки.
